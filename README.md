# PowerAgent

LLM 驱动的多相 Buck 供电模块参数寻优 Agent。

在一个**昂贵、会失败、带硬约束**的仿真环境里，由大模型提出候选参数、由确定性代码做全部安全判定与判分，闭环搜索满足电气约束的设计点，并产出可审计的报告。

199 项测试（约 45 秒，无需 MATLAB），CI 每次 push 全量执行。

## 三个可复算的结果

**一、在 144 点设计空间上，模型三次独立运行都命中了档位上的全域最优解。**

参考扫描把 12×12 个批准档位组合逐点跑完，36 个点满足全部硬约束，其恢复时间从 5.2 µs 到 383.2 µs（中位 33.2 µs）。以此为参照系，只更换提案来源、其余评价路径完全相同：

| 提案来源 | 运行次数 | 命中第 1 名 | 排名 |
| --- | --- | --- | --- |
| LLM（DeepSeek） | 3 | **3** | 1, 1, 1 |
| 均匀随机采样 | 5 | **0** | 2, 2, 4, 5, 23 |

记录：[`artifacts/solution_quality_report.json`](artifacts/solution_quality_report.json)。随机侧种子写在记录里可原样复现。**限制**：达标线（10 µs）区分不出两者——随机侧 4/5 也达标了，144 点的空间里随机撞上 5 个达标点之一并不难；能区分的是"是否命中全域最优"。样本量小（3 与 5），结论仅限本任务。

**二、模型输出的候选一次通过确定性校验的比例为 15/15。**

档位值要求 7 位有效数字（`28480.3586844`，相对容差 1e-6）。校验器不静默吸附、不裁剪：偏离档位或越界一律拒绝并落 `rejections` 表。最近一次完整寻优 3 轮、15 个候选全部通过，56002 token，43 次引擎启动（上限 200）。记录：[`artifacts/llm_search_report.json`](artifacts/llm_search_report.json)。

**三、参考扫描的最优解暴露了约束集缺失一半的稳定性判据。**

第一次扫描的"最优"落在设计域角点，恢复时间 2.2 µs，但增益裕量只有 1.917 dB——接近失稳。60 个"可行"点里 24 个（40%）的增益裕量低于 6 dB。成因是硬约束有 `phase_margin_min = 45°` 却没有增益裕量下限，而 45°/6 dB 是配对的判据，配置只取了相位那一半。最优化精确地利用了这个未被约束的自由度。

补上第五条约束后重跑：可行点 60 → 36（正好排除那 24 个），最优变为 `rcomp=28480.4 Ω, ccomp=100 pF` → 5.2 µs / PM 73.0° / GM 9.19 dB。变更理由与证据记在 [`docs/design/requirements.md`](docs/design/requirements.md) 的 AC1 变更记录里（`hard_constraints` 节变更需重新审批）。

## 为什么不是又一个 LLM 调用脚本

三个信任域，边界由 Python 包结构强制，不靠约定：

| 域 | 模块 | 权限 | 明确**没有**的权限 |
| --- | --- | --- | --- |
| 确定性域 | `controller` `eval` `store` `report` `config` | 全部安全判定与事实写入 | 不生成候选 |
| LLM 域 | `agent` | 依只读状态输出 3~6 个候选与搜索假设 | 不调仿真、不写状态、不判分、**不决定自己被校验的严格度** |
| 仿真域 | `sim` + MATLAB `+pa` | 唯一有权访问模型文件 | 不接受任意 MATLAB 命令、寻优期只读 |

由此得到的性质：

- **判分权与提案权分离**：约束判定、worst-case 聚合、排序全在 `eval`，LLM 不参与，杜绝"自己给自己打分"。
- **LLM 输出必过确定性校验器**：单位归一、合法域、档位对齐、重复与新颖度。被拒候选连同具名原因（`out_of_domain` / `off_tick` / `duplicate_of_tested` / …）落 `rejections` 表并关联到产生它的那次 `llm_calls`，不静默丢弃。
- **两类失败严格分开**：输出不合 schema → 回灌错误清单修复（计入 `max_llm_repair_rounds`）；网络失败/超时 → 指数退避（计入 `max_network_retries`）。共享计数会双向坏事：网络抖动会耗尽模型的修复机会，模型答错会触发无意义的重试。
- **上下文按信息而非按长度压缩**：波形采样点禁止进入 prompt，先确定性压缩为 6 个特征（超调/下冲/恢复时间/纹波/振荡频次/发散标志）。实测压缩比 35007 → 6。
- **prompt 可复现**：相同状态产出逐字节相同的文本与 `context_hash`。`context_hash` 取自规范化状态而非文本——取自文本则排版调整就会改哈希，而缓存与复现判等依赖那个等价关系。
- **成本有闸**：仿真调用次数、墙钟、token 三维度预算账本，触顶熔断；两级缓存键复用昂贵仿真结果。
- **状态可重建**：SQLite 是唯一事实源，进程崩溃后从数据库重建搜索状态，支持断点续跑。
- **分层执行有真实成本梯度**：筛选层用平均模型（7.5 ms），只有通过筛选的候选才进入评价层的开关模型（360 ms）——实测相差 **48 倍**。
- **模型变更使旧结论失效**：模型依赖闭包的全部文件内容参与 `model_package_hash`，与冻结记录不符即拒绝启动。
- **报告不下结论**：报告渲染库里已有的事实，`推荐理由` 与 `限制说明` 两段留空给人写。采纳与否是人工决定。

## 被优化的对象

一个 4 相同步 Buck 变换器，把板级 12 V 中间总线降到 0.8 V，额定 200 A。待整定的是 Type-II 补偿网络的 `Rcomp` / `Ccomp`，它们决定环路零点位置，进而决定负载突变时输出电压掉多深、多久恢复、以及还剩多少稳定性裕量。

| | |
| --- | --- |
| 拓扑 | 4 相交错，每相 500 kHz；L = 150 nH/相，Cout = 6 mF，ESR = 0.15 mΩ |
| 控制 | **电流模式**（电流内环 + 电压外环），Type-II 跨导补偿器 |
| 工况 | 筛选 12 V / 25 °C；评价 10.8 V / 85 °C，负载 100 A → 150 A 阶跃 |
| 设计变量 | Rcomp ∈ [1 k, 100 k] Ω，Ccomp ∈ [100 p, 10 n] F，各 12 个对数档位 → 144 点 |
| 硬约束 | Vout ∈ [0.75, 0.85] V；相电流峰值 ≤ 55 A；相位裕量 ≥ 45°；增益裕量 ≥ 6 dB |
| 优化目标 | 最小化最恶劣工况下的恢复时间，达标线 ≤ 10 µs；并列时比相位裕量 |
| 搜索预算 | 200 次仿真调用，2 小时墙钟，连续 3 轮无改善即停 |

**为什么是电流模式**：低压大电流的 LC 输出网络阻尼极小（Q ≈ 4），电压模式下这对双极点在穿越频率处贡献 −180°，而 Type-II 只有一个零点、最多补回 +90°，**无论怎么整定都拿不到 45° 相位裕量**。想靠 ESR 零点补相位就得把 ESR 加到 mΩ 量级，那时 ESR×ΔI 的瞬时压降会吃光全部电压容限。电流内环把电感极点消掉、功率级降为一阶，Type-II 才够用。

**两个变量各管一个方向**：Rcomp 定带宽，太小则下冲超限、太大则高频开环增益（趋于常数 `Rcomp·gm·ESR/Ri`）超过 1 而失稳；Ccomp 定补偿零点位置，太小则零点落在穿越频率之上、补不回相位。相位裕量约束管下界，增益裕量约束管上界——这正是上面第三个结果的由来。

物理数值是自洽的设计假设，量级取自低压大电流 VRM 的常见区间，**未绑定实测数据或具体器件 datasheet**。所以结论是"这套搜索方法在该电路上有效"，而不是"这组参数可以投产"。

## 快速开始

```bash
pip install -e ".[dev]"
python -m pytest                              # 199 passed，约 45 秒，无需 MATLAB 与 API Key
```

跑真实寻优需要 DeepSeek API Key：

```bash
cp .env.example .env                          # 填入 POWERAGENT_LLM_API_KEY
python scripts/llm_search_run.py              # 一次完整寻优 → artifacts/llm_search_report.json
```

不需要 API Key 的部分：

```bash
python scripts/dense_grid_run.py                        # 144 点参考扫描 + 响应面图
python scripts/solution_quality_compare.py --random 5   # 随机对照
python scripts/margin_cross_check.py                    # 裕量双方法交叉核对
python scripts/dual_model_consistency.py                # 平均/开关模型一致性
```

渲染报告（示例产出见 [`artifacts/comp_tuning_v1/reports/`](artifacts/comp_tuning_v1/reports/)）：

```bash
# CLI 固定读仓库根的 runs.db（design.md 未定义 --db 选项），而脚本把库写在带
# 时间戳的工作区里，所以先复制过来。<时间戳> 用 artifacts/llm_search/ 下最新的一个。
cp artifacts/llm_search/<时间戳>/runs.db .
poweragent report --task comp_tuning_v1
```

同一个库重复渲染得到逐字节相同的报告（报告里不写渲染时间）。

## 已验证的性质

下列都是测试套件实际断言的内容：

**分层执行的成本梯度是真实的**：平均模型 7.5 ms、开关模型 360 ms，相差 48 倍。前者不含开关纹波（稳态峰峰 < 10 µV），后者产生真实纹波（约 1.8 mV）与相电流三角波（单相峰峰约 11.7 A，与解析值一致），并使相电流峰值抬高约 5 A——所以 `peak_current_max` 只在评价层才有实际约束力。

**两个保真度描述同一个电路**：稳态输出偏差 0.0048%（容差 0.5%），负载阶跃下冲偏差 8.25%（容差 10%）。这份核对是分层执行的前提证据，并已抓到过一个真实的建模错误（采样延迟漏了相数）。

**裕量提取有两条独立路径且完全一致**：数值状态空间线性化与手写解析传递函数，在四个探测点（含一个不可行点）上偏差为 0.0° / 0.0 dB。

**指标实现经反向核对**：用解析已知的构造波形按 `metrics.yaml` 的文字定义手算期望值再比对实现——这个顺序抓到了一个滤波器边界伪影 bug（稳态恒定 0.804 V 被报出 0.402 V 的纹波）。反过来做（读实现写期望）抓不到。

**结果可复现**：同一候选同一场景两次求解逐位相同，且与仿真总时长无关。

**报告不越界**：8 个统计推断词、4 类实物可行性表述、4 类效率表述在模板与渲染产物中都不出现；过程量（首次可行解轮次、可行候选率、重复率）不进入结论段的渲染上下文——这一条靠结构保证（结论段用独立命名空间单独渲染），不靠命名约定。

## 开发期证据记录

两份记录由脚本产出并入库，各自被 preflight 校验：

```bash
python scripts/margin_cross_check.py       # → artifacts/margin_cross_check.json
python scripts/dual_model_consistency.py   # → artifacts/dual_model_consistency.json
```

前者内容是确定性的（无时间戳、固定小数位、规范化序列化），其 sha256 被 `metrics.yaml` 绑定——一份每次重跑都会变哈希的记录会迫使配置跟着改，那等于没有门禁。后者内嵌 `model_package_hash`，**改动任何模型文件都会使它失效**：两个保真度是否一致的结论只对当时那份模型成立。

CI 每次都重跑这两个脚本并比对哈希。这一步不是在检查代码，而是在检查那两条门禁本身还成不成立。

## 已知边界

- 阶段 1 为**仿真轨**（`simulation_only=true`）。未做实测校准，结论不足以支撑打板。
- 以下模块在范围裁剪中被明确移除，非"待补全"：模型校准、工程知识检索、鲁棒性三维扫描、寄生参数敏感性、双模型一致性的运行期门禁与并行仿真回退。
- MATLAB/Simulink 通路为可选高保真后端。所在环境为共享网络许可证且并发常满，主链路走 Python 仿真后端；因此 MATLAB 交叉验证由"平均/开关双模型互核"这条替代路径承担。
- 两处数值偏差已测量并记录：开关模型在 20 ns 显式欧拉步长下对下冲高估约 3%（相对 5 ns 的收敛值），方向保守；其初始状态不是精确的稳态相位，在 1 ms 仿真时长下残余影响低于 0.5%。双模型容差因此设为 10%，构成写在配置注释里。
- 频域裕量用精确纯延迟表达采样保持，时域求解用一阶滞后近似它。这个分裂是有意的：纯延迟会把 ODE 变成延迟微分方程，而一阶滞后的相位下界是 −90°，会让增益裕量在数学上无界、进而被下游判为提取失败。
- 对照实验的样本量小（LLM 3 次、随机 5 次），设计空间只有 144 点。数字支持"在本任务上 LLM 稳定命中最优而均匀随机不能"，不支持更强的一般化。
- `poweragent report --approve` 的审批链未打通（`_compute_current_result_hash()` 未实现），不影响报告渲染。
- CLI 的数据库路径固定为仓库根的 `runs.db`（design.md 未定义 `--db` 选项，不凭空新增一个未登记的接口面），而寻优脚本把库写在 `artifacts/<脚本>/<时间戳>/` 下以便多次运行互不覆盖。两者之间需要手工复制一次，见上面的命令。

[`docs/design/design.md`](docs/design/design.md)（架构与逐项口径裁定）、[`docs/design/requirements.md`](docs/design/requirements.md)（EARS 需求）。两份文档写在编码之前，并经过三轮范围削减——被删掉的组件清单同样记录在案。

按信息密度，实现代码里的 docstring 记录了每处偏离设计文档的理由。挑几个例子：为什么采样延迟是 `0.5/(N·fsw)` 而不是 `0.5/fsw`（错值使平均模型系统性悲观 20%，而**偏悲观不等于安全**——筛选层会误杀实际可行的候选，且误杀者不会进评价层纠正）；为什么裕量提取失败不改 `runs.status` 而记在 `metric_results.valid` 上（`runs.status` 描述引擎执行，而引擎确实跑通了）；为什么新颖度比较要加 `1e-9` 容差（`.12g` 格式化使"恰差一整档"算成 0.999999999999，朴素严格比较会整批误拒相邻档位候选）。
