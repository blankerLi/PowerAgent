## 三、一页项目说明（作品集 / 邮件附件用）

### 问题

多相 Buck 供电模块的补偿网络整定：两个参数决定负载突变时输出电压掉多深、多久恢复、环路还剩多少稳定性裕量。评价一个候选需要跑开关级仿真（单次 360 ms），且候选可能不可行。这是一个**每次试错都要付费、而且会失败**的带约束搜索问题。

### 做法

由 LLM 提出候选参数，由确定性代码做全部安全判定与判分，闭环搜索并产出可审计报告。三个信任域的边界由 Python 包结构强制：

| 域 | 权限 | 明确没有的权限 |
| --- | --- | --- |
| LLM | 依只读状态输出 3~6 个候选与搜索假设 | 不调仿真、不写状态、不判分、不决定自己被校验的严格度 |
| 确定性 | 全部安全判定与事实写入 | 不生成候选 |
| 仿真 | 唯一有权访问模型文件 | 不接受任意命令、寻优期只读 |

关键工程决策各有取舍依据，例如：校验器放在 controller 层而非提案器内部（否则被校验方同时握有校验规则）；`context_hash` 取自规范化状态而非渲染文本（否则排版调整就会破坏"相同状态"的等价关系，而缓存与复现判等依赖它）；报告的结论段用独立命名空间单独渲染（否则 Jinja2 的作用域继承会让"过程量不进结论段"成为一句空话）。

### 结果

**有效性**：把 12×12 个批准档位组合逐点跑完建立参照系（36 个点满足全部硬约束，恢复时间 5.2 ~ 383.2 µs，中位 33.2 µs），然后只更换提案来源、其余评价路径完全相同：

| 提案来源 | 运行次数 | 命中第 1 名 | 排名 |
| --- | --- | --- | --- |
| LLM（DeepSeek） | 3 | 3 | 1, 1, 1 |
| 均匀随机采样 | 5 | 0 | 2, 2, 4, 5, 23 |

**限制**（与结果同等重要）：达标线区分不出两者（随机侧 4/5 也达标）；样本量为 3 与 5；设计空间只有 144 点。这些数字支持"在本任务上 LLM 稳定命中最优而均匀随机不能"，不支持更强的一般化。

**输出可用性**：档位值要求 7 位有效数字（相对容差 1e-6），校验器不静默吸附、不裁剪。最近一次完整寻优 3 轮 15 个候选全部一次通过。

**从数据中发现的设计缺陷**：第一次参考扫描的"最优解"落在设计域角点、恢复时间 2.2 µs，但增益裕量只有 1.9 dB——接近失稳。追查发现硬约束有相位裕量 45° 却无增益裕量下限，而 45°/6 dB 是配对的判据；60 个"可行"点里 24 个（40%）增益裕量不足。补上第五条约束后重跑，可行点 60 → 36，最优解换位。**最优化会精确地利用任何未被约束的自由度**。

### 工程质量

199 项测试（约 45 秒，无需 MATLAB 与 API Key），CI 每次 push 全量执行。两份门禁证据记录（裕量双方法交叉核对、平均/开关双模型一致性）内容确定性、sha256 被配置绑定，CI 重跑并比对哈希——这一步检查的是那两条门禁本身还成不成立。

三处已测量并如实记录的数值偏差、五个被明确裁剪（非"待补全"）的模块、一处未打通的审批链，全部写在 README 的"已知边界"里。

### 边界

阶段 1 为仿真轨（`simulation_only=true`）。物理数值是自洽的设计假设，量级取自低压大电流 VRM 的常见区间，未绑定实测数据或器件 datasheet。结论的效力止于"这套搜索方法在该电路上有效"，不构成选型或打板依据。报告模板中**不存在**渲染"可打板""实物可行"这类表述的分支。
